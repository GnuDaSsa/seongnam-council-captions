# 실시간 수집본의 로컬 보관

공유 자막 수집에 `--archive-dir <보관함 폴더>`를 추가하면, 자막을 실제 생성한 회의의 수집이 끝나거나 중단된 뒤 같은 서버의 `/api/live/minutes` 전체 수집본을 읽어 기존 보관함의 TXT, HWPX와 목록을 갱신한다. 옵션이 없으면 보관 동작은 실행되지 않는다. 보관본은 공개 회의 자막의 자동 생성 초안이며 원음 확인이 필요하다.

```powershell
python tools/shared_stt.py --endpoint https://<자막-서버> --end-at 2026-11-26T18:00:00+09:00 --meeting-id 2852 --archive-dir <보관함-폴더>
```

기본 소스에서는 수집기가 `tools/build_caption_archive.cjs`를 찾고 빌더가 `dist/exports.js`로 문서를 만든다. 빌더를 별도 폴더로 옮겼다면 `exports.js`도 그 옆에 두고 `--archive-builder <빌더 경로>`를 지정한다. 시안 서버가 읽는 `archive` 폴더를 `--archive-dir`에 지정하면 보관함에 새 자료가 나타난다. 각 수집본은 확인된 종료 시각 또는 마지막 수집 시각부터 14일 동안 목록과 다운로드에서 사용할 수 있다.

서버 연결 실패, 응답 오류, 빈 수집본, 유효하지 않은 회의 메타데이터, 기존보다 줄어든 수집본 또는 보관함 갱신 오류가 발생하면 오류를 표시하고 기존 목록을 보존한다. 실패한 회의는 수집을 다시 시작하지 않고 다음과 같이 명시적으로 재시도할 수 있다. 여러 회의는 `--meeting-id`를 반복한다.

```powershell
python tools/shared_stt.py --endpoint https://<자막-서버> --meeting-id 2852 --archive-dir <보관함-폴더> --archive-retry
```

수집 중단은 회의가 종료되었다는 뜻이 아니므로 완료 시각을 만들어 넣지 않는다. 자동 저장은 로컬 파일을 갱신하며, 독립 HTML에 이미 내장된 목록은 자동으로 고쳐 쓰지 않는다. 보관함 서버의 목록이나 별도로 갱신한 HTML을 사용한다.

## 사이트에서 내려받기

편성표가 다음 회의로 넘어가도 새로 수집한 회의는 수집 당시의 의원·직원 명부로 자막을 다시 판정할 수 있다. 과거 자료에 그 명부가 저장돼 있지 않으면 기존 저장 표기를 유지한다.

사이트의 ‘회의 기록 → 실시간 자막 보관함’은 서명된 수집본 중 자막이 있는 회의를 표시한다. 수집 완료는 완료 시각부터, 중단 또는 예정 시각이 지난 상태 미확인 수집본은 마지막 실제 자막 시각부터 14일 동안만 보관 API가 전체 자막을 제공한다. 정확히 만료 시각이 되면 목록과 다운로드 API에서 제외한다. 현재 진행 중인 수집본, 자막이 없는 회의는 표시하지 않는다. 예정이 지난 수집본에 종료 상태가 없으면 종료로 단정하지 않고 ‘종료 여부 미확인’으로 표시한다.

새로 서명된 수집본에는 당시 공식 회의 식별·제목·시간·공식 링크가 함께 저장되어, 이후 생중계 편성표가 교체돼도 보관 목록을 구성할 수 있다. 이전 상태에 그 메타데이터가 없던 2852·2853·2855는 `dist/data/archive-seed-meetings.json`의 당시 공식 메타데이터와 기존 수집본을 결합한다. seed에는 자막 내용이 없으며 기존 저장소에 실제 자막이 없으면 목록에 생기지 않는다. 그 밖에 메타데이터 없이 이미 편성표에서 사라진 과거 회의는 자동으로 복원할 수 없다.

`/api/archive/catalog`과 `/api/archive/meetings/<id>`는 같은 서버 규칙으로 만료를 검사한다. 사이트는 후자에서 받은 자막으로 이 브라우저에서 TXT와 HWPX AI 생성 초안을 만든다. 원본의 불확실 표지와 공식 중계 링크를 포함하며, 공식 회의록을 대체하지 않는다. 누락된 저장 페이지나 조회 오류는 실패로 표시하고 불완전한 문서를 만들지 않는다. 보관 목록 조회가 저장소 한도를 초과하면 일부 목록을 완전한 것처럼 표시하지 않고 오류를 반환한다.

14일은 이 **보관함을 통한 다운로드 공개 기간**이다. 이 변경은 원천 BUCKET의 기존 객체를 삭제하거나 기존 `/api/live/minutes`와 그 보존 정책을 변경하지 않는다. 사용자가 이미 받은 파일도 회수하지 않는다. 읽기 전용 `tools/serve_local.mjs --captures <수집본 폴더>`는 동일 보관 API를 파일 기반 수집본으로 제공한다.

로컬 미리보기는 실행 중 `dist/data/live-meetings.json`을 다시 읽어 화면과 생중계 API에 같은 편성을 적용한다. 편성 파일이 비어 있거나 작성 중이면 마지막으로 검증한 편성을 계속 보여 준다. 앞서 열었던 편성의 수집본은 보관함에서 읽을 수 있다.

## 로컬 검증

소스 폴더에서 Worker 검증을 실행한다. 기본 검증은 테스트에서 만든 작은 수집본을 사용한다. 배포 패키지의 `source` 옆에 `evidence/captures`가 있으면 실제 수집본 세 건도 검증한다. 다른 경로의 수집본을 사용하려면 `COUNCIL_ARCHIVE_CAPTURES`에 폴더를 지정한다.

```powershell
node --test tools/test_archive_worker.mjs
# 캡처의 실제 경로를 지정할 때
$env:COUNCIL_ARCHIVE_CAPTURES = 'C:\path\to\evidence\captures'
node --test tools/test_archive_worker.mjs
```

브라우저 검증은 Python Playwright와 Chrome을 사용한다. 첫 터미널에서 미리보기를 실행하고 두 번째 터미널에서 같은 주소를 넘긴다. 실제 수집본 세 건이 미리보기 시계에서 만료 전이면 `--expect-real`을 사용한다. 수집본이 없거나 모두 만료된 서버에는 `--expect-empty`를 사용한다. 시각을 고정한 Worker 검증에서는 만료가 지난 뒤에도 세 수집본을 재현할 수 있다. `--screenshot`을 지정하면 검증 화면을 해당 파일로 저장한다.

```powershell
node tools/serve_local.mjs --port 4186 --captures ../evidence/captures
python tools/test_archive_browser.py --url http://127.0.0.1:4186 --expect-real
```
